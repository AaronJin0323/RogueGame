```python

FAMILY = "Enemies"                    # SourceArt/Enemies/, and the licence row's family

def build_swarm():                    # called on an empty scene; leave mesh objects in it
    ...

MESHES = {"SM_Enemy_Swarm": build_swarm, "SM_Enemy_Swarm_Optic": build_optic}
```

```powershell
& Tools\blender\Mesh.ps1 -Source Tools\blender\enemy_swarm.py          # build and import
& Tools\blender\Mesh.ps1 -Source Tools\blender\enemy_swarm.py -Cook    # and cook it alone
& Tools\blender\Mesh.ps1 -Source Tools\blender\enemy_swarm.py -Check   # the committed SourceArt file is what the source builds
& Tools\blender\Mesh.ps1 -SelfTest                                     # the pipeline itself
```

- Commit three things per mesh: the source, `SourceArt/<Family>/<name>.fbx`, `Content/DT/Meshes/<name>.uasset` (the last two through LFS). The licence row is already there (§3); the script refuses a family with none.
- Units and axes, as read on the test triangle (Blender size 1.000 x 0.500 m imported as 100.0 x 50.0 uu, minimum Y -50.0): one Blender unit is one metre and 100 uu; +Z is up; Blender +X is Unreal +X; **Blender +Y is Unreal -Y**.
- All mesh objects a function leaves are joined into one static mesh. A material slot keeps its name and gets the default material: no material or texture asset is imported, no collision is built, Nanite is off. Assign the game's generated materials in code.
- The export is byte-reproducible (fixed clock and stable ids in `build_mesh.py`). A different Blender is refused. The `.uasset` is not byte-reproducible: the editor stamps it.
- Not built: LODs (package B's render path owns that call), vertex animation, anything skeletal. Not a gate step: Blender is not started by the gate; run `-Check` in the package's own acceptance.

Materials and other editor-made assets: write `Tools/assets/<family>_*.py` (editor Python, ends by logging `<file name without .py>: DONE`) and run it with `Tools\EditorPython.bat Tools\assets\<file>.py`. It is a commandlet: no window, no renderer. Package A extends `Tools/create_arena.py` and runs `Tools\CreateArena.bat` as before.

## 4. Add a smoke scene and take its golden

A scene is `Tools/Scenes/<name>.json` (lower case, digits, underscores). `Scenes` in `Tools/tools_test.py` checks every file.

```json
{
	"note": "what the frame is for",
	"gate": "smoke",
	"judge": "golden",
	"cultures": ["en", "zh-Hans"],
	"weather": "Dusk",
	"seconds": 11,
	"cmds": ["DT.God 1", "DT.Hero.Walk 4000 4000"]
}
```

- `cmds`: console commands that exist in `Source/` (`DT.*`), one per entry, no comma and no quote. `DT.Hero.Walk <x> <y>` puts the hero somewhere; the plate's corners are at `C.ARENA.HALF_EXTENT_UU` and the hero clamps short of them.
- `seconds`: sim time of the shot (default `C.SMOKE.SECONDS`). The sim is held on that step and shot after it settles, so the frame does not depend on the frame rate. `director`: true turns the run director on. `seed`: an explicit seed; without it a tool run is on seed 0.
- `judge`: `golden` (against `Docs/Validation/goldens/<name>_<culture>.png`), `contrast`, or `dormant_line`. `gate`: `smoke` (goldens), `contrast`, or `none` (run by hand only).
- `elements`, for a `contrast` judge: the elements the frame is staged to show, from `telegraph`, `enemy_rim`, `optic`, `tracer_core`, `hero`, `gem`, `chest`. Only those are judged. Without it all seven are required, as in the gate's own frame.
- `weather`: the pin. Only `Dusk` exists; a scene must name it, so that when a second weather is built every golden still shows one state.

```powershell
& Tools\Smoke.ps1 -Scene edge_corner -Culture en -Update        # take or re-baseline a golden, on the hidden desktop
& Tools\Smoke.ps1 -Scene edge_corner -Culture zh-Hans -Update
& Tools\Smoke.ps1 -Scene edge_corner -Culture en                # judge it; prints SMOKE: PASS|FAIL
```

The shot is `Saved\Smoke\<name>_<culture>.png`. A golden is a record, not a proof: the image check lets a whole frame move pass far under its limit (`Validation/S4_wave1.md` §5 item 3), so each package's own checks carry acceptance. By that item a package re-baselines **only the goldens of its own scenes**, in its merge commit, with before and after frames in its validation note. `arena_empty`, `combat_staged` and `edge_corner` belong to P0: package A will move `edge_corner` and probably `arena_empty`, B and C `combat_staged`; name the golden in the report and the scheduler re-baselines it at merge. Every scene costs one launch per culture in the gate, about a minute each; give a scene one culture unless it shows text.
