# S4 outdir root: the look's Tools scripts write only inside their own tree

**The fault.** On 2026-11-13 `Tools\HeroZone.ps1 -OutDir Saved\HeroZone_before` wrote its four shots under the engine's own folder, `E:\UE5\UE_5.8\Engine\Binaries\Win64\Saved\HeroZone_before`, not under the worktree: the script handed the relative folder on to the game (`-DTShot="<OutDir>\<tag>.png"`), and the engine resolves a relative path on its command line against its binaries folder. Older folders found there the same way (`BotRuns` of 30 October; `EliteAnchors`, `Logs` and `Session` of 12 November) were not traced to one script; the holes that could write them are named below.

**The rule.** Nothing a Tools script of the look hands the engine names a place outside the worktree it runs in.

**The helper.** `Tools/OutDir.ps1`, dot-sourced, one function: `Resolve-DTOutDir <path> <root> [-Default <path>]` returns an absolute path inside the root or throws a message naming the path and the root. Empty takes the caller's default; a relative path is joined to the root; every path is normalised (`[IO.Path]::GetFullPath`) and must then lie inside the root, compared without regard to case and with a trailing separator (`E:\Tree2\x` is not inside `E:\Tree`). Refused: `..` that climbs out, an absolute path elsewhere, another drive, a UNC or device path (`\\server\share`, `\\?\`, `\\.\`), a drive-relative path (`E:x`), a path rooted at the current drive (`\x`), the root itself (also as `Saved\..` or with a trailing separator), an invalid path, and nothing at all with no default. It creates and deletes nothing, follows no junction, and holds nothing of the look, so the shared launchers can dot-source it too.

**Who goes through it.** `HeroZone.ps1` (`-OutDir`, the fault), `Frames.ps1` (`-OutDir`, still relative to the tree, now refused outside it), `EnemyArt.ps1` and `ImpactArt.ps1` (their fixed folders under `Saved`). In all four the output folder and `Saved\Logs` are resolved right after the processor mask and before `Enter-DTHeavy`, and every `-DTShot=` and `-ABSLOG=` path is passed through the helper where it is built. `ImpactArt.ps1 -Scenes` names, which become file names, must be lower case, digits and underscores, checked at the same place. A refusal is the script's own FAIL line and exit 1, for example `FRAMES: FAIL (-OutDir E:\Other\x is outside this worktree E:\Dusktracer\...)`: no slot is taken and nothing is launched. `Tools/tools_test.py` `OutDirRoot` holds the helper's cases, a text test that every path argument of the four is the helper's, and runs of `Frames.ps1`, `HeroZone.ps1` and `ImpactArt.ps1` refused on a lock directory held alone with no engine at `UE_ROOT` (no `heavy:` line, no slot file, no folder made).

**A consequence.** A run can no longer shoot into another worktree (for example the Visual session's `Saved\S4Report\...` with an absolute `-OutDir`): it shoots into its own tree's `Saved`, and the frames are copied to where they are handed in.

**Still open in the shared launchers (for Mechanics, after the carry).** `RunTests.ps1 -Log` hands a relative path to `-ABSLOG=` unrooted (the same fault as `HeroZone.ps1`). `BotRuns.ps1 -Out` (the source of `-DTBotOut=` and `-ABSLOG=`) and `S2Exit.ps1 -Out` (handed to `BotRuns.ps1`) have been made absolute with `Resolve-Path` since 675ffcf of 30 October, but against the shell's own folder and anywhere on the machine. The same lines fit each: dot-source `Tools/OutDir.ps1`, resolve the parameter after the mask and before `Enter-DTHeavy`, and print the script's FAIL line on a refusal.

**Not verified.** No build ran and no game was launched for this job: a real launch writing into the tree from a relative `-OutDir` is seen the next time a built tree runs `HeroZone.ps1` after this lands.
