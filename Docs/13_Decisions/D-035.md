# D-035 — On a save the duos' door opens the duo card; the reactions start when that card is taken

- **Date:** 2026-11-09
- **Decider:** scheduler (delegated, D-009)
- **Class:** RULE
- **Status:** applied

## Context
The review of `dev/s3` at `5ccf82e` (`Validation/S3_review_fixes.md`, its one blocker). `Reaction.Duos` gates the whole reaction stage (`reactions.md` R-REA-02), not only the duo card. On a save, `TwoPaths6` writes it and a gated run passed it to the sim at run start, so a run with the same picks dealt different damage on a profile that had earned the door: Plasma, Writ, Deep Ledger and the rest fire on owned blessings alone, with no card taken. That is a number a save raises, against D-023 and `meta.md` R-MET-28 ("a door widens a pool and raises no number").

## Options
- A — Keep it and reword R-MET-28. A save would then change what the same picks do, which is the one thing D-023 rules out.
- B — Gate every run's reactions on the duo card, tool runs included. It changes the S2 stage the `S2_duos.md` battery read, outside a fix.
- C — On a gated pool only: the save's `Reaction.Duos` opens the duo card (R-REA-08) and does not reach the sim at run start; taking any `Blessing.Duo.<Pair>` starts the stage for that run. A tool run's `DT.Unlock` / `-DTUnlock` is unchanged.

## Decision
C. The door widens the pool by one card, and the reactions are what that card brings, so a run that takes no duo card plays the same on every profile. Code: `DTOffers::OpensAtRunStart`, `DTOffers::OpensStage`, `UDTOfferSubsystem` (run start, `MakePool`, `Pick`).

## Hypothesis
We believe a save no longer moves a number for a run that took no card, because the stage is shut until a card is picked; measured by T-MET-28 (`Dusktracer.Meta.KeeperDoors`) and `Tools/MetaCheck.ps1` step I, which still reads the duo card in a gated hand. Revisited if a person at the external S3 session reads the reactions as missing before the card.

## Impact (dependency sweep)
- Rules: `meta.md` R-MET-28 (the duos' row), `reactions.md` R-REA-02.
- Constants: none.
- Files / tests: `DTOfferGenerator`, `DTOfferSubsystem`; T-MET-28.
- Stream: none at run start; a gated run that takes a duo card unlocks the stage at that pick, a step boundary, so a seed still replays for its profile (R-MET-16).
- `S2_duos.md` and every tool battery: unchanged, they unlock the stage by switch.
