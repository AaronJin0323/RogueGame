# D-014 — Catalogs compile into generated C++ tables and native tags

- **Date:** 2026-10-30
- **Decider:** scheduler (delegated, D-009)
- **Class:** RULE
- **Status:** applied

## Context
AGENTS non-negotiable 4: tuned values are data generated from `Docs/09_Catalog/*.csv` and `constants.yaml`, never hand-copied. The S1 specs name data assets (`DA_*`, `UDTWeaponDef`) as the runtime form, but nothing yet needs in-editor authoring, and assets are binary (LFS, unmergeable, not diffable).

## Decision
For S1, `Tools/gen_catalog.py` turns the catalogs into constexpr tables in `Source/Dusktracer/Core/DTCatalogGen.h` (namespace `DTCat`) and native gameplay tags in `Core/DTTagsGen.*`, committed like `DTConstantsGen.h` and kept in sync by the gate step `catalog` (check mode). Cells naming a `C.` key resolve to the generated constant. Conventions: empty numeric cell = 0; doc-only columns (`tag ref effect notes note Source ref_reached_s`) are not emitted. Generated files are regenerated on merge, never hand-merged. Where a spec says `DA_*`/`U…Def`, read "generated catalog row" until a data-asset need appears (then: generate the assets from the same CSV, never hand-author them).

## Hypothesis
Text-only, generated tables keep parallel agents merge-safe and the catalog the single source; revisit if a designer needs in-editor authoring (S4+).

## Impact
`07_Technical §6`, `Tools/Gate.ps1` (`catalog` step), every S1 code package.
