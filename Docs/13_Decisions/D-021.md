# D-021 — The `Dusktracer` module builds `/fp:precise` in every target

- **Date:** 2026-10-31
- **Decider:** scheduler (delegated, D-009)
- **Class:** RULE
- **Status:** applied

## Context
UBT builds the editor target `/fp:precise` and game targets `/fp:fast`, so a seed's result did not carry between them (`Validation/S2_package.md`, Editor hash against package hash). Seed 101 died at 617 s in the editor and won at 993 s in the package. Bot batteries read the editor; players play the package. R-TEC-15 lived with that as two families.

## Decision
`FPSemantics = FPSemanticsMode.Precise` in `Dusktracer.Build.cs`. The module's flag only; the engine stays as it is. R-TEC-15 is reworded: one family. It replaces the two-family rule and stacks nothing on it.

The line was set before reading: keep it only if editor, Development and Shipping agree on `input_hash` on all of 30 full runs, and game p95 rises under 0.3 ms with budgets met.

## Result
Both met. Readings in `Validation/S2_package.md`, One float mode.
- **30/30** on `input_hash` for every pair of the three builds, seeds 101 to 130. The kept `/fp:fast` Development, the control, reads 0/30 against each.
- **Game p95 in a Development package:** caps scene +0.01 ms, S2 scene -0.05 ms, inside the spread of the runs. Budgets met.

`Tools/Perf.ps1` launches the editor, which was `/fp:precise` already, so it cannot see this flag. The frame cost was read in the package; the tool's own reading is kept as the control. Shipping has no CSV profiler, so Development stands in for it.

## Impact
- `Dusktracer.Build.cs`; `07_Technical` R-TEC-15, T-TEC-15; comments in `Tools/PackageRestartCheck.ps1` and `DTBotSubsystem.h`.
- Editor results do not move, so no bot battery is owed again. Every game-side hash moves: a hash or outcome read from a package before this no longer describes a package, and seed 101 now dies at 617 s there too.
- Not guaranteed: engine code is still compiled by target, and hashes are compared by reading rather than on each package. Read again when the engine or the compiler changes.

## On main
Ported to the S1 validator build, numbered as on `dev/s2`. `Validation/S2_package.md` and `Tools/PackageRestartCheck.ps1` arrive with `dev/s2`, so T-TEC-15 reads PLANNED there until they do. The readings above are `dev/s2`'s; on main, seeds 101 to 110, Storm/Tempest, bot v1, skill 1.0, no time cap:
- **10/10** on `input_hash`, outcome and end time for every pair of editor, Development and Shipping, through `Tools/Package.ps1`. A `/fp:fast` Development of the same commit, the control, reads 0/10 against the editor.
- **Editor unchanged:** `input_hash`, outcome and end time equal before and after on all ten, 7 wins and 3 deaths.
- `steps` reads one apart with equal hashes on seeds 103 and 106 (Shipping) and 110 (the editor against itself), and 103 is a win. Frame cost was not read again on main.
