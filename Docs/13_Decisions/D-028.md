# D-028 — The hub takes the one seed rule; Shipping's fresh draw is read on Development

- **Date:** 2026-11-01
- **Decider:** scheduler (delegated, D-009)
- **Class:** RULE
- **Status:** applied, with one reading moved to Development (see Decision 3)

## Context
D-025 was made on `main`, where every launch starts a run. On `dev/s3` a person's launch stops in the hub, and a run starts only at Begin (`vigil.md` R-VIG-01, R-VIG-07). `Validation/S1_human_seed.md` listed what that breaks at this merge: the hub read the removed `GetCommandLineSeed` and treated `0` as no seed, a bad `-DTSeed` would sit in the hub, every human launch of `Tools/SeedCheck.ps1` would wait out its timeout, and two rules say what a tool run is.

## Decision
1. `DTHubFlow::BeginSeed` holds R-VIG-07. A launch's first run takes a named seed, `0` included. Every later run draws. A launch naming none runs on its hub world's own fresh seed, from `UDTSimSubsystem::GetLaunchSeed`. A tool that forced the hub with no seed draws, as it did: `-DTHub` runs are proofs of a person's path, and seed `0` belongs to runs a tool starts itself.
2. The rejection comes before the hub, in `ADTGameMode::BeginPlay`, so a bad `-DTSeed` exits with code `2` on a person's launch too.
3. `SeedCheck` reaches a run through `-DTHubCheck=Begin`, real key events from the Shrine to Begin, not a tool flag, so the launch stays a person's. That flag is not in Shipping, and Shipping has no way past the hub with no hands. So T-PKG-04 reads the launchers, an explicit seed and both rejections on Shipping, and the fresh draw on the package's Development build with the launchers' own arguments. Shipping's fresh draw itself is not read. It is the same `FDTRunSeed::ForThisLaunch`, and R-TEC-15 holds the two builds to one family, but that is an argument and not a reading.
4. The two tool rules stay apart. `FDTRunSeed::IsToolRun` is `-unattended` or automation; `UDTMetaSubsystem::IsToolRun` (R-MET-14) adds `-DTBot*` and `-DTNoSave`. A `-DTNoSave` launch with no seed and no `-unattended` skips the hub and the save yet draws a fresh seed, because a launch that falls back to seed `0` unasked is the bug D-025 removes.

5. `FDTRunSeed` reads the `-DTSeed=` switch alone. A map on the command line can carry `?DTSeed=` (`Tools/WinCheck.ps1`), and the strict read took that text for a bad switch, so the way back to the hub exited with code `2` after a win. That seed is the map's, read by `ADTGameMode::ParseSeed`.

## Impact
- `DTRunSeed`, `DTHubFlow`, `DTHubSubsystem`, `DTGameMode`, `DTHubCheck`, `Tools/SeedCheck.ps1`; R-TEC-16, R-VIG-07, R-MET-14, R-PKG-04, T-VIG-07, T-PKG-04, T-TEC-16.
- Replaces nothing on `main` or `dev/s2`, which have no hub.
- Launchers name no seed, so `Validation/S3_package.md`'s "`Play_*.bat` gives one `-DTSeed`" describes that branch and not this one.
