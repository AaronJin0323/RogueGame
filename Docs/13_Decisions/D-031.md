# D-031 — `FDTRunSeed` reads the `-DTSeed=` switch alone on every branch

- **Date:** 2026-11-01
- **Decider:** scheduler (delegated, D-009)
- **Class:** RULE
- **Status:** applied

## Context
`FParse::Value` accepts a match after any character that is not a letter or digit, so `DTSeed=` also matched `?DTSeed=` inside a map on the command line. Only whitespace ends the value (R-TEC-16), so `L_Arena_Test?DTSeed=9100?DTPatron=Storm` read as the seed `9100?DTPatron=Storm` and was rejected. `dev/s3` had fixed this for its own way back to the hub; `main` had not. Evidence: `Validation/S1_seed_switch.md`.

## Decision
1. `FDTRunSeed` matches `-DTSeed=` and nothing else, on `main` as on `dev/s3`. R-TEC-16 already says `-DTSeed=<n>`, so no rule text changed.
2. A map's `?DTSeed=` belongs to the map. On `main` it has no reader, so that launch stays on a tool's `0` or draws a person's fresh seed; on `dev/s2` and `dev/s3` `ADTGameMode::ParseSeed` reads it. `ParseSeed` is not brought down, because it belongs to the restart path.
3. `DTSeed=9107` and `/DTSeed=9107` are no longer read as a seed. No script in `Tools` uses either.

## Impact
- `input_hash` on seed 9107 is unchanged on the one arm the track read, Steered Storm Tempest.
- `DTRunSeed.cpp` and its test are the same bytes as `dev/s3`, so D-028's item 5 and this record say one thing. D-028 said it replaced nothing on `main` or `dev/s2`; this record is that replacement.
