# D-026 — Run telemetry records say what the run did; applied and raw are named

- **Date:** 2026-11-01
- **Decider:** scheduler (delegated, D-009)
- **Class:** RULE
- **Status:** applied

## Context
Reading the owner's run (`2147483647_20261031_231306`, build `996cd47`, one designer run, not a validator session) showed records that did not say what the run did: casts logging 0 hit and 0 damage beside about 1000 `Keeper.Storm` applied, `swarm_ttk_s` reading spawn to death against a bound of 0.3 s, no weapon or modifier records, the fatal hit in no block, and `run_start.input_device` a field with one possible value. Class BUG in the records; the meanings below are the calls that had to be made to fix them (`Validation/S1_run_telemetry.md`).

## Decision
- `swarm_ttk_s` keeps its name and takes the true meaning: first hit to death of a Swarm enemy (R-TEL-03, R-TEL-06). Spawn to death is gone, not renamed: nothing reads it.
- A cast's record is a window, not a tag: a hit counts when it lands from `Keeper.<Base>` or the layer's `Keeper.<Path>` between the cast's start and one step after its end. It is attribution; R-KEE-15's marginal stays `Tools/probe.py`'s.
- `damage` is applied everywhere and a raw reading says so (R-TEL-11). `boss_end.damage_taken_by_attack` becomes `damage_raw_by_attack`; a cast the run cut short is `complete` false and stays out of the means.
- The fatal block closes in the Hero phase of the fatal step (R-DIR-15); the boss fight is a block.
- A round's source is its firing point. `hero_damaged` on a `Bullet` hit adds `vel_x vel_y flight_s`. `FDTHeroHit::Position` is the hit's source for every writer.
- Weapon records are written by `UDTWeaponSubsystem`, not by `FDTWeaponSim`.
- `run_start.input_device` is removed; the CSV column reads the real device per interval. `run_start.wall` is UTC.
- `C.TEL.HERO_POS_INTERVAL_S` is 2.5 s, a telemetry cadence, not a balance number.

## Result
The sim did not move: on seed 9107's five arms the hash, outcome, end time, picks and dashes match. No number was tuned on any reading here.

## Impact
- Old run files keep the old meanings. `bot_summary.py` and `pressure.py` refuse them for the changed fields rather than mixing them.
- Readings of `intercession.damage` taken before this are raw.
- `dev/s2`'s `bot_summary` reads `intercession.damage` and picks up the applied meaning at this merge.
