# D-054 — A slowed run is told by its slow share; the threshold is set at the S1 gate

- **Date:** 2026-11-11
- **Decider:** scheduler (delegated, D-009)
- **Class:** RULE (method, `10_Tuning.md §2`)
- **Status:** decided 2026-11-11; the text is in the job `s1/forge-truth`, the tool line follows `s1/gate-main`

## Context
`Validation/plans_audit.md` 4.6, `telemetry.md` R-TEL-08 and Open, `Validation/S1_d047_reread.md` ("The machine"), the evidence digest of 2026-11-11.

- D-046's job made `run_end` write `wall_dropped_steps` and the wall duration. The handover asked how many dropped steps set a run aside.
- One dropped step is one sim step of wall time the sim never ran: a frame that owes more than `C.SIM.MAX_SUBSTEPS` steps runs that many and discards the rest (`Core/DTFixedStep.cpp`). The game then runs slower than the clock, which is an easier game. Paused time is never counted.
- By the code a dropped step changes wall speed only. The step sequence and its inputs are the same however many drop, so a seed's result does not move. No paired run has compared it yet.
- A person at a steady 30 frames a second or more drops nothing. Below that, at f frames a second, the sim loses (60 − 2f) of every 60 steps: a sixth of the time at 25. One hitch of a quarter second drops 13 steps, which is nothing over a run.
- A bot at `-DTBotFast` steps past the clock while the clock still ticks beside it, so its count says nothing about the machine. The 135 build runs of the reread dropped 2082 steps in 130 runs, 0.363 % of steps at most; the 1000 probe scenes dropped none because no clock frame of theirs is counted at all.
- `telemetry.md` Open already leaves the threshold to the S1 gate decision.

## Options
- A — A count. It grows with the length of the run.
- B — A share of steps, set now from a number nobody has read on a slow machine.
- C — The share, printed for every run a person plays and judged nowhere until session A has given values.
- D — Wall time over sim time. For a person it is one plus the share, so it is the same measure with the pause arithmetic added.

## Decision
C.

1. **Slow share** of a run is `wall_dropped_steps` over the steps run plus `wall_dropped_steps`: the part of unpaused time the sim did not simulate. `10_Tuning.md §2` defines it, and a session note prints it for every run beside the count.
2. **It is read on people's sessions only.** A run at `-DTBotFast` is printed as not read, never as zero.
3. **No threshold before people.** The S1 gate decision sets it from session A's values, as a named constant with its row in the number log. Until then a note lists the runs by slow share and sets none aside.
4. **A dropped step is not a different game for a seed.** The pinned rerun in flight compares the count beside the results; if results ever move with it, that is a BUG in the sim, not a matter for this measure.

## Hypothesis
We believe printing the slow share lets the S1 gate tell a slowed session from a normal one, because a frame rate held under 30 gives a share of (60 − 2f)/60 and a hitch gives almost none; measured by session A's notes carrying the value for every run; reverted in favour of wall over sim time if a validator reports slow motion on a run that read a share near zero.
