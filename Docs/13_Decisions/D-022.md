# D-022 — S3 starts on `dev/s3` before the S1 and S2 exit tests

- **Date:** 2026-10-31
- **Decider:** scheduler (delegated, D-009; owner: "continue developing, no stop, you make every decision")
- **Class:** GO-NOGO
- **Status:** applied

## Context
The stage table bars meta progression until S1 exits and bars nothing further for S3 once S2 exits. S1's exit needs O-008; S2's exit reads 1 PASS, 3 FAIL, 2 NOT READ, and two of those need humans. All automated S2 work is done. H03 §4 lets the pipeline queue work past an unplayed checkpoint and forbids merging feel-changing systems past it.

## Options
- A: stop until humans read S1. Nothing moves.
- B: build S3 on its own branch; no exit is declared passed.

## Decision
B. `dev/s3` is cut from `dev/s2`. `main` stays the S1 build, `dev/s2` stays S2. Neither exit test is waived: S1 and S2 stay open, and S3 cannot exit before them. Shape constants are not locked, so S3 reads every number from `constants.yaml` and hard-codes no balance assumption. Nothing on `dev/s3` that raises in-run power merges back to `dev/s2` or `main`. Meta widens the card pool and does not raise numbers (blueprint pillar 5); where the old tree grants stats, the spec flags it instead of building it silently.

## Impact
`dev/s3` branch; `Docs/02_Systems/meta.md`; `Docs/03_Narrative.md`; S3 rows of `12_Production`. Replace point: if a human reading changes the S1 shape constants, S3 costs and unlock lists are re-read, not the save format.
