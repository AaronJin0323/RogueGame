# D-029 — A tool launch runs on a hidden desktop; no flag is the no-window rule

- **Date:** 2026-11-01
- **Decider:** scheduler (delegated, D-009)
- **Class:** RULE
- **Status:** applied

## Context
The owner's standing rule is that a tool run shows nothing on their desktop. It was held by launch flags, script by script, and windows still reached the desktop. Tool launches also shared `%LOCALAPPDATA%\Dusktracer` with the owner's run files, and `PadCheck` deleted there. Evidence, what really shows a window, and the one breach by this work: `Validation/S1_no_windows.md`.

## Decision
1. R-TEC-17: every start of `UnrealEditor.exe`, `UnrealEditor-Cmd.exe` or `Dusktracer.exe` by a tool goes through `Tools/HiddenLaunch.ps1`, on a hidden Win32 desktop with no console window. No flag stands in for that. A commandlet (`-run=`) is exempt. `Tools/Play.bat` and the packaged `Play_*.bat` are a person's launches and the only ones that open a window.
2. Every package launch by a tool names a `-userdir` under `Saved`. A tool never writes to or deletes from `%LOCALAPPDATA%\Dusktracer`.
3. The gate gains a step, `windows` (`Tools/WindowCheck.ps1`, T-TEC-17): a bot, a smoke and a test run show no window on the real desktop, read by a hook on `EVENT_OBJECT_SHOW`, with a probe and a bypass control in every gate. `HiddenLaunchGuard` in `Tools/tools_test.py` fails on a launch past the helper, by text.
4. The `tests` step moves to `Tools/RunTests.ps1`, with a timeout; a run killed on it fails, whatever its log counts.
5. `Start-DTHidden` returns a real `Process`, so a script's move onto it is a one-token swap. For the editor only the launched process is in the script's job, so a shared `zenserver` lives; for a packaged game the whole tree is, because `Dusktracer.exe` is a stub whose real game is its child.

## Impact
- `input_hash` on seed 9107 is unchanged on 5 of 5 arms, and the goldens hold (`S1_no_windows.md`).
- The rule covers every launch script on every branch: `dev/s2` and `dev/s3` move theirs at their merges.
- The brief's reading that `-nullrhi` opens a real game window was not reproduced: 3 launches, 0 windows, hook on the desktop. The sample that was seen stays unexplained. The rule does not rest on either reading.
- Limits: the hook reads one desktop, a window given `WS_VISIBLE` by `SetWindowLong` fires no event, and the text guard cannot follow a launch behind a function or alias.
- `Docs/STATE.md` still names `-nullrhi` and `-RenderOffScreen` on its no-windows line until its next rewrite.
