# D-033 — `run_start` says what made the run: `config` and `driver`

- **Date:** 2026-11-09
- **Decider:** scheduler (delegated, D-009)
- **Class:** RULE
- **Status:** applied

## Context
The S3 exit needs each run to say who played it, and `run_start` held no such field, so a tool could only guess a person's run from how it played. `dev/s3-kit` took the field and asked for its D-number at integration (`Validation/findings_S3.md`, call 7; `Validation/S3_kit.md`).

## Options
- A — guess from play: refused, a bot can play like a person and a short run reads like a quit.
- B — two fields on `run_start`, the build configuration and a verdict on the launch, never the command line.

## Decision
B, as `telemetry.md` R-TEL-13 states it. `config` is the build configuration (`Shipping` is the validator build; `Development` covers `Tools/Play.bat` and the proof build). `driver` is `bot` with any `-DTBot*` switch; `tool` with `-unattended`, under automation, or with any other `-DT*` switch, a named seed included, but for `-DTHubCheck`; `person` otherwise. Only the verdict is written. A file with neither field is from before this rule and reads as unknown, never as a person's. R-TEL-08 compares two launches only on one build with one driver; the CSV carries neither field.

## Hypothesis
We believe two fields move the S3 exit's reading of who played a run from a guess to a field, because `run_start` held nothing that named a person; measured at the external S3 session by `Tools/S3Exit.ps1` on the validators' zips; reverted if a validator's real run reads anything but `person` on Shipping.

## Impact (dependency sweep)
- Rules: `telemetry.md` R-TEL-13 (new), R-TEL-08; `package.md` and `Validation/S1_kit.md` on what a run file holds.
- Constants: none.
- Files / tests: `DTTelemetryCore`, `DTTelemetryRecords`, `DTTelemetrySubsystem`; `Dusktracer.Telemetry.*`; `Tools/s3_exit.py` refuses a file without them.
- `input_hash` reads no telemetry field, so no seed's reading moves.
- Open: `driver` `person` on Shipping is read on the editor build only, since Shipping cannot reach a run with no hands (`S3_kit.md`).
